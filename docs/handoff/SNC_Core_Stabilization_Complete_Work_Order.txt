PART III — DURABILITY CLASSES

APPLIED = in-memory change. LOCAL_DURABLE = crossed local persistence boundary. HA_DURABLE = crossed persistence boundary required by automatic-failover contract. SETTLED = all durable distributed obligations completed.

Verify rather than assume: sync replicated DURABLE OK → HA_DURABLE; async replicated DURABLE OK → LOCAL_DURABLE but not necessarily HA_DURABLE; cross-group transfer OK → durable debit + durable obligation but not necessarily SETTLED. Separate acknowledgement durability from distributed settlement.

PART XI — BOUNDED WORK

Normative proposal: A single unit of work MUST NOT monopolize an execution domain long enough to violate health, liveness, or control-plane responsiveness. Large work should be bounded/resumable. PART XII — 100K FALSE-FAILOVER INSTRUMENTATION

Build one monotonic correlated timeline for migration PREPARE/chunks/SEAL/final copy/STAGE/COMMIT/ACTIVATE; destination shard progress/long ops/admin arrival-response/starvation; WAL append/flush/fsync; replication send/receive/durable ack; witness STATUS/last-good/suspicion/threshold/Paxos/promotion/fencing; relevant CPU and queue depths. PART XIII — CAUSAL TRACE DESIGN
