F11 — APPROVED

Normalized duplicate endpoints are refused; localhost/address aliases and multiple local addresses reaching the same local witness port are caught; --id must identify this witness; local identity uses interface addresses rather than bindability.

Keep the documented residual: a remote witness host named through two NIC addresses cannot be inferred as one physical acceptor. Profile B requires one configured address per witness host.

F10 — APPROVED

Legacy interpretation is now based on unambiguous line shape. Modern numeric machine names remain modern. Unknown READ no longer creates persistent state. Mixed/malformed state fails closed. H8/H9 cover the important round trips.

FATAL PERSISTENCE — APPROVED

Temporary open/write/fsync, rename, directory open and directory fsync are checked. Failure stops the witness before a safety-dependent reply. H6/H7 exercise PREPARE, ACCEPT, COMMIT and proposer-learning paths. This closes the ordinary durability-failure path into F9.

F9 INITIAL PROFILE B EXCLUSION — APPROVED

After this hardening, the remaining deliberate rollback histories may be excluded from the initial experiment.

Unsupported/invalid:
- individual witness state/directory restore;
- individual witness VM/container/filesystem/hypervisor rollback;
- stale/other witness state copied into an identity;
- storage replacement followed by reuse of the old witness identity;
- --new-state used to recreate an existing quorum member.

If trustworthy witness state is lost: STOP THE RUN. Do not resurrect that identity.

The full recovering-acceptor protocol remains future work and is NOT authorized now.

WITNESS BACKUP/RESTORE SEMANTICS — APPROVED

Keep the distinction permanently:
application-state snapshots/PITR/branches are different from Paxos acceptor local state. An individual consensus member cannot be rolled backward into a quorum that continued progressing.

G2 — NARROW CORRECTION

WitnessStateGuard itself updates monotonic marks on every check(). Good.

But bench/lab/lab.py currently records after initial creation and calls check_witness_state() at end of run.

Therefore the lab integration is not a continuous monitor. A rollback that later progresses beyond the initially recorded marks could theoretically be invisible at the end.

This does NOT reopen F9 as a blocker because operator/hypervisor rollback is explicitly excluded. But the documentation must match reality.

Preferred correction:
call check_witness_state() at meaningful campaign boundaries:
- before/after any witness restart if one is ever performed;
- before/after fault/action phases relying on witness authority where practical;
- scenario/round boundaries;
- end of run.

Each check advances the recorded monotonic marks and narrows the detection window.

Do NOT build a background watcher.

If periodic checks materially complicate the lab, keep end-only checking but explicitly document that G2 detects rollback/replacement only when the evidence remains observable at the check; it is not continuous anti-rollback protection.

Given the existing helper, periodic boundary checks are preferred.

G2 FILE IDENTITY — ACCEPTED

Do not pin the state-file inode: normal save-by-rename changes it.

Directory device/inode + run nonce + fixed path + monotonic machine state is reasonable for this campaign guard. It is not a general anti-rollback mechanism.
