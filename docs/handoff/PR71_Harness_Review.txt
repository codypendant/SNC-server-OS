PR #71 REVIEW — HA TEST-HARNESS RACE FIXES

DECISION

PR #71 is APPROVED.

The two pre-existing HA test-harness races identified during S0/S0.1 validation are fixed without changing engine, server, witness, protocol, checkpoint, or runtime behavior.

This clears the validation-harness blocker in front of S1. No R640 load is required.

1. LAB p3 PRIMARY RACE — APPROVED

Lab.wait_primary() is a correct replacement for the one-shot primary() sample in p3.

Accepted properties:
- bounded timeout;
- polls all group members each round;
- returns only when exactly one member claims primary;
- zero claimants means “not yet known”;
- multiple claimants are treated as transient ambiguity;
- node id 0 is valid;
- timeout reports last roles.

The deterministic scripted test correctly reproduces the original None race, two-primary ambiguity, node id 0, and bounded no-primary failure.

Keep primary() unchanged elsewhere for now.

2. READY-LINE RACE — APPROVED

c2_restart_held now:
- waits only after witness READY is observed;
- waits for the NEW process’s READY line;
- is bounded at 30 seconds;
- ignores refused READY lines;
- uses the first accepted READY line from the restarted process;
- preserves the grounding rule that after-v must be >= the restarted primary’s own NOT READY version.

The old process is isolated in old_nodes, so pre-restart output cannot satisfy the condition.

The deterministic late-line reproduction demonstrates the original race.

3. NEGATIVE PATHS — APPROVED

The test still fails when:
- READY line is absent;
- READY line is stale.

This confirms the wait did not weaken the semantic assertion.

4. VALIDATION — ACCEPTED

Evidence is sufficient:
- lab witness guard Release 10/10;
- c2 Release 10/10;
- ASan+UBSan 5/5 each, zero reports;
- TSan 5/5 each, zero reports;
- 3 stressed parallel rounds pass;
- deterministic race reproductions pass;
- negative paths fail correctly;
- full RelWithDebInfo suite 37/37.

No engine C++ changed, so no new full engine sanitizer campaign is required solely for this test-only PR.

5. HARNESS STATUS

The two known validation races from PR #70 are CLOSED.

Future failures in these scenarios must be investigated from first principles rather than dismissed as the old race.

6. S1 MAY NOW BEGIN

S1 behavioral implementation is AUTHORIZED.

S1 scope:
- resource-specific admission;
- separate unrelated durable READ admission from mutation follow-up backlog;
- waiter-budget admission;
- WAL-buffer-budget admission;
- reserve/check BEFORE first irreversible mutation;
- keep kEmitBacklog=1024;
- keep E_OVERLOADED as wire status;
- expose limiting resource through refused_by gauges;
- already-acknowledged/internal/follow-up work remains non-refusable;
- no checkpoint pacing/I/O changes;
- no scheduler-loop reordering unless strictly required for correctness.

7. S1 BUDGETS — DERIVE, DO NOT GUESS

Do not blindly use earlier placeholders.

Before choosing defaults, document:
- measured waiter/result memory;
- WAL active/flushing memory behavior;
- worst-case object + local-peer + session record bytes;
- per-shard and total memory envelope;
- recovery/drain and tail-latency implications.

Tiny explicit test limits are fine for deterministic gate testing.

Production defaults may remain provisional if conservatively derived and explicitly revisited before S6.

8. RESERVE-BEFORE-MUTATE

Admission must occur:
after validation,
before first state mutation.

Worst-case WAL sizing must cover every synchronous record generated by the call.

A transient preflight check is acceptable only while the current no-yield/single-shard-thread assumption is proven and documented.

If that assumption is not true, use an explicit reservation.

A refused mutation must leave object/version/session/WAL/follow-up state unchanged.

9. INTERNAL WORK MUST DRAIN

Do not mechanically apply client admission budgets to:
- acknowledged follow-up apply;
- recovery replay;
- standby apply;
- migration/install;
- internal durability work required for progress.

Client admission must never deadlock the work needed to drain the constrained resource.

10. READ ADMISSION

Do not implement “all reads bypass overload.”

Only resource-independent durable reads should bypass mutation follow-up backlog.

Reads using waiters, forwarding, pending slots, SRI rings, index gather resources, or output buffering remain bounded by those resources.

11. LOOP ORDER

Keep scheduler loop order unchanged in S1.

Do not bundle reap_io/ring/app_poll/checkpoint_step reordering with admission changes.

12. REQUIRED S1 TESTS

At minimum:
- durable owner-local reads succeed while follow-up backlog >1024;
- new mutation/create gets E_OVERLOADED from follow-up backlog;
- waiter budget refuses before admission;
- WAL budget refuses before first mutation;
- refused mutation leaves all state untouched;
- sequenced retry/idempotency survives admission refusal;
- local-peer + session + object WAL sizing is sufficient;
- internal/follow-up work drains while client admission is closed;
- refused_by gauges identify exact cause;
- read flood does not starve durability/backlog progress;
- legacy admission switch, if retained, restores old behavior;
- persistence/session/transfer/replication/migration/crash suites remain correct.

13. CC CONTRACTS

If implementation unexpectedly touches checkpoint/recovery semantics, stop and return for review.
